# AGENTS.md.template 变更记录

这份记录只有一个用途：**让 `sdd-upgrade` 知道「本包往模板里加过哪些条款」**，好在已经落地的
用户 `AGENTS.md` 里逐条核，只补缺的那几条。

为什么不整份 diff：用户的 `AGENTS.md` 落地之后就是他自己的文件，里面有大量**合法**的自有改动
（改过的路径、删掉的不适用条款、自己加的内容）。整份 diff 会把这些全报成差异，而噪音一多，
人就开始整段跳过——假警报比漏报更致命，这条在本包别处已经写过。

**改模板必须同步在这里记一笔。**这条没有机器锁兜底（锁标题集合管不住「往已有节里加一条」这种
改法，锁 sha256 又会在任何措辞微调时误红），靠纪律守。漏记的后果是那条新规则永远到不了老仓库。

## 怎么读这张表

`探针` 那一列是**在用户 AGENTS.md 里搜的原话**——搜得到就是已经有了，搜不到才需要补。
探针要挑该条款里最不容易被改写的那一小段：太长会被合法的措辞调整弄失效，太短会误命中别处。

## 2026-09-07 · 协作形态三档

背景：SDD Loop 原本的模型是「一个仓库、一份状态、一个活跃 Loop」，单人开发没问题；多人并行时
它是一把全仓库串行锁，而人会绕过锁干活，绕过之后没有任何治理。

| 条款 | 在哪一节 | 探针 | 为什么加 |
|---|---|---|---|
| 确认留痕 | 文档规则 | `必须在该文档里留痕` | **常驻，任何项目都要补。**只在对话里说「用户同意了」，会话一结束就只剩一个 `confirmed`，没人分得出它确认的是哪一版 |
| 确认人的决定权 | 文档规则 | `确认人对这块范围有没有决定权` | 多人档。拿旁人一句「可以吧」标 confirmed，这道门禁等于不存在 |
| 代码事实要核新旧 | 事实优先级 | `需要核对新旧的事实` | 多人档。并行时读到的代码可能是别人推了一半的中间态 |
| 冲突不得自行解决 | 事实优先级 | `涉及别人正在做的范围时` | 多人档。「我判断这样更合理」和「对方已经确认过了」在盘上长得一样 |
| 分流状态入口 | Loop 状态入口 | `状态每条流一份` | 分流档 |
| `--stream` 与别的流报红 | Loop 状态入口 | `别的流报红不是你停工的理由` | 分流档 |
| 流内编号 | SDD 与 Loop | `Loop 编号是流内编号` | 分流档。跨流重号正常，引用带流名；只管 Loop 编号，条款编号不受影响 |
| 流的划分与跨流改动（整节） | 新增一节 | `## 流的划分与跨流改动` | 分流档。流怎么划、怎么认领、跨流走 platform 流、platform 活跃期间的互斥 |
| 本流限定 | 事实优先级 | `第 2~4 档指的都是` | 分流档 |
| 归档按流分 | 文档规则 | `归档必须按流分开` | 分流档。共用归档根会让 A 流去校验 B 流的文档——错误归属，成片假警报 |
| backlog 条目带归属 | 文档规则 / Requirements / Implementation | `每一条都要写明归属` | 分流档。不按流筛，开局会把别人的欠账也摆一遍，噪音会让人跳过整个环节 |

同批：模板顶部引导注释重写，说明「源项目迁移」是**要加什么**、「单人开发/单流：删掉」是
**要删什么**，两种方向别搞反。

## 2026-09-06 · docs/backlog.md

本轮不做的缺陷此前没有落点，只在会话里说一句「先记下」，会话一结束就没了。

| 条款 | 在哪一节 | 探针 | 为什么加 |
|---|---|---|---|
| 记进 backlog | Implementation | `记进 \`docs/backlog.md\`` | 常驻。不落盘等于没记 |
| 开局捞 backlog | Requirements | `开一轮新 Requirements 前先读` | 常驻。捞出来交用户逐条拍板，不得替用户删；为空也要说一句 |
| backlog 是跨 Loop 常驻文件 | 文档规则 | `是**跨 Loop 常驻**文件` | 常驻。不属于任何 Loop，不参与门禁，不随 Loop 归档 |
