# Property-Based Testing（PBT）

目标：从规格中提取始终成立的不变量，用大量生成输入验证，而不是只检查少量固定样例。

适用：Parser、序列化、金额/库存/权限规则、状态机、排序、分页、幂等、去重、并发和重试。纯文档、样式或没有稳定不变量的改动可写 N/A。

## 没有 PBT 库时

1. 有现成 PBT 库：沿用，不另起体系。
2. 没有库但属性简单：使用现有测试框架加测试目录内的确定性随机生成器。
3. 生成或 shrinking 很复杂：在 Architecture 和 Tasks 记录依赖变化，取得用户授权后才增加成熟库。
4. 不存在有价值的不变量：写 N/A 和具体理由。**“没有 PBT 库”本身不是 N/A 理由。**

轻量生成器必须记录：Property、固定且可覆盖的 seed、样本数、正常/边界/非法/极端输入域；失败时输出 seed、序号和输入。修复后把人工缩减出的最小反例固化为普通回归测试。不要在项目里自造通用 PBT 框架。

PBT PASS 必须在审计事件里带 `caseCount` 和 `seed`；PBT 不替代关键业务示例和集成测试。
