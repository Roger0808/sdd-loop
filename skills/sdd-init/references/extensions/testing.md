# Testing

目标：证明验收条件已经实现，并给未来改动留下回归保护。

1. Requirements：标出必须由自动化测试证明的成功标准。
2. Architecture：确定单元、集成、端到端和必要人工检查的边界。
3. Specification：建立“验收条件 → 测试类型”映射，包含正常、失败、权限和边界路径。
4. Tasks：测试是独立完成条件，不允许最后补一句“加测试”。
5. Implementation：Bug 修复优先增加失败复现；选择与 change surface 成比例的测试范围。
6. Verification：记录原样命令、环境、退出码、结果、失败项和未覆盖范围。

禁止删除断言、放宽预期或改变业务语义来换取绿灯。失败项不能只写“与本次无关”，必须给出可复核证据。
