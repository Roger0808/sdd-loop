# 上线执行清单

`release-checklist.md` 是一次 Solo 需求唯一的上线执行入口。它由主仓维护，集中列出所有参与仓的发布动作、执行顺序、SQL、项目配置、FilerUI 配置、验证和回滚；不能把这些信息分散在聊天记录或各仓临时说明里。

## 保存位置

- `full`：与 `repositories.json` 放在同一个 demand unit 根目录。
- `openspec-light`：与 `repositories.json` 放在同一个 OpenSpec change 的 `sdd-solo/` 目录。

从 `assets/release-checklist.md` 复制模板后填写。`repositories.json.releaseChecklist.path` 使用相对 `repositories.json` 的路径，默认就是 `release-checklist.md`。

## 生成与冻结时机

可以在设计或 Tasks 阶段先写草稿，但必须在最终交付提交、轻量结果报告或完整模式候选冻结之前补全。所有参与仓实现和验证稳定后，按最终代码、部署方式和环境事实复核一次，然后：

1. 删除所有占位符和待定项；
2. 每个必填章节至少保留一个复选项；
3. 不涉及 SQL、项目配置或 FilerUI 时，写成 `- [x] N/A — 原因：<具体原因>`，不能留空或只写“无”；
4. 每个 participant 都必须在“发布项目与顺序”中出现一次；不需要发布的仓也写 `N/A` 和原因；
5. 把文档中的清单状态和 `repositories.json.releaseChecklist.state` 都改为 `ready`，记录 `preparedAt`；
6. 计算忽略复选框勾选状态后的规范化 SHA-256，写入 `releaseChecklist.sha256`，再运行 `sdd-loop solo check`。

`ready` 只表示上线事项已经写完整，不表示实际发布已经执行。提交前允许动作项保持 `[ ]`。只有动作已经真实执行或明确属于 N/A 时才能写 `[x]`，Agent 不得预先代勾。

## 内容要求

清单要短，但必须足够让一个不了解本次对话的人照着执行：

- 发布项目与顺序：逐仓写环境、发布物或版本来源、动作、依赖前置和验证点；编号就是执行顺序。
- SQL 脚本：写目标库/环境、仓库内相对路径、执行顺序、执行条件、校验和回滚。不得粘贴账号、密码或连接串。
- 项目配置：写项目、环境、配置项或文件位置、变更动作、生效方式和验证；敏感值只写密钥引用或受控来源，不能写明文。
- FilerUI 配置：写环境、namespace/group/dataId 或等价定位、配置键、变更动作、生效/验证和回滚；不能写敏感值。
- 发布后验证与回滚：写冒烟、监控、业务核对、回滚触发条件、各仓回滚顺序和负责人。

若清单包含 `TBD`、`TODO`、`待确认`、`待补充` 或模板占位符，机器检查必须失败。清单正文变化会使旧 Solo 收口凭据失效；只把已有复选项从 `[ ]` 改成 `[x]` 或反向恢复不会改变固定的计划指纹，因此可在实际上线时持续勾选。

## 单一权威与参与仓

此清单是跨仓执行计划，只在主仓维护，不复制成各参与仓可编辑版本。参与仓的 `dependencies.md` 仍只记录本仓相关依赖；需要了解完整上线顺序时，以主仓清单及其在 Solo 收口凭据中的指纹为准。
